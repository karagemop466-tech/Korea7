Why the portal said “Predicted values must be in range [0, 1]”

The submission page accepts a single-band GeoTIFF (or a zip holding one) and enforces that predicted values lie in [0, 1]. A file can violate this in three ways. All three were reproduced and are now impossible in this repo's writer.

CauseHow it happensHow this repo prevents it
NaN inside the footprint The competition's own training_features.tif uses the float32 sentinel −3.4028235e+38 as nodata. Carry it through a transform and clip, and NaN or the sentinel survives into the predicted area. grid.write_like writes an explicit float32 array; format_gate counts non-finite pixels inside the footprint and fails if the count is not zero. The generated file reports 0.
Sentinel values −3.4e38 or −9999 written outside the studied area but inside the raster still fails a whole-array range check. The generated file is 0.0 outside the footprint, not NaN and not a sentinel, so every one of the 12,279,160 cells is finite and inside [0, 1] under any reading.
Unnormalised scores A raw z-score, distance in metres, or probability logit written straight to disk. The emitter only ever writes 0.0 or 1.0. There is no continuous path to the writer.

The convention question: NaN outside, or 0 outside?

The official sample_submission.tif uses NaN outside the footprint (7,111,787 cells) and 0/1 inside it. That is the organiser's own convention, so it is accepted. This repo uses 0 outside instead, because 0 is finite and therefore cannot fail a range check under any validator implementation. The cost is nil: outside the footprint the label raster is nodata, so those cells are not scored.

What the generated file contains, measured

  • Driver GTiff, 1 band, float32, EPSG:32611, 3730×3292.
  • Geotransform identical to sample_submission.tif.
  • Non-finite pixels inside the footprint: 0.
  • Values: exactly two distinct values, 0.0 and 1.0.
  • Dots: 27,159.

These are read from evidence/candidate_gates.json, produced by scripts/build_candidate.py.

Flagged for review. The exact portal message and the exact file that produced it were never captured in this programme, so no root cause is asserted here with certainty. What is asserted is narrower and verifiable: the file generated now cannot trigger any of the three mechanisms above, because it has no non-finite value anywhere and no value outside [0, 1].
