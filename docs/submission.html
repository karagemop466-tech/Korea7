How to submit a file to the DOE GEMS competition

Status of the file in this repo: DO NOT SUBMIT

The generated GeoTIFF passes the format and uniqueness gates but its MODEL-ESTIMATE is 0.0434 (95% 0.0199–0.0655) against an owner-reported programme best of 0.2778. Uploading it cannot improve standing. The steps below are here so that the file can be submitted deliberately if you decide otherwise, and so that the mechanics are documented once.

Before you start — the four things that actually matter

  1. Format. A single-band GeoTIFF, or a .zip containing exactly one GeoTIFF. CRS, shape and geotransform must match the submission format exactly: EPSG:32611, 3730 rows × 3292 columns, pixel size 100 m, origin (243350.0, 4508550.0). scripts/validate_submission.py and src/gems/grid.py:format_gate check this offline.
  2. Values. Finite and in [0, 1] everywhere inside the footprint. See the range-error page for why the portal rejected a file before.
  3. Name and note. The portal asks for a submission name and a note of ≤ 140 characters. Use the name recorded in evidence/run_card.json so the file on the leaderboard can be matched back to the evidence here.
  4. One slot. The weekly submission cap is shown on the submission page; promotion is a separate decision from building. Do not spend a slot on a file that has not cleared all four gates in evidence/candidate_gates.json.

Step by step

  1. Open the competition page and sign in. The data and submission tabs are login-walled; they are not reachable from an automated sandbox, which is why nothing here was uploaded automatically.
  2. Go to the Submit tab. The form reads New submission with a File to submit chooser and an optional Note field, then a Create button.
  3. Choose the file: docs/downloads/k7-oslf-lat11-n27159-20261104T210000Z.tif. Verify its SHA-256 first: 
    ebdf0342273688a26dab6a5bbd539b17b8d8cfa98355b63b406c095cc268c7b7
    On Linux/macOS: shasum -a 256 <file>; on Windows: certutil -hashfile <file> SHA256. If the hash differs, the file was altered: stop.
  4. Paste the note from evidence/run_card.json (140 characters or fewer):
    11px coverage lattice modulated by INGENIOUS declustered seismicity, 3px catalogue collar removed
  5. Press Create. The next screen shows the score after the organiser's evaluation completes. Copy that page verbatim into evidence/organizer_receipts/ — that is the only thing that turns an owner-reported number into an ORGANIZER-CONFIRMED one, and this programme has never had one.
  6. Record the outcome in evidence/run_card.json next to the estimate, and note whether the estimate was inside its interval. That is how the estimator in src/gems/estimate.py gets calibrated.

When the four gates pass

python scripts/build_candidate.py exits 0 only when all four gates pass, and the site banner flips from DO NOT SUBMIT to OK TO SUBMIT. Until that happens, treat every download as a research artefact.

What not to do

  • Do not re-upload any of the nine focus-site files. All nine are within 3 px of a sister file for 99.98–100% of their dots, and re-submitting an existing placement is exactly what the brief forbids.
  • Do not submit a file whose only difference from a previous submission is a re-encoding (-nan versus -zeros). GEMSDOE25 and GEMSDOE30 are the same 44,090-dot placement and both scored 0.2600.
