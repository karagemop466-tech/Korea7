Submission guide

The steps below are a future workflow, not a recommendation to submit an existing file.

Before using a weekly slot

  1. Generate an independently constructed candidate using permitted competition data and the shared writer. Record a unique name and a note of at most 140 characters.
  2. Run the shared segment-blocked, buffered holdout with catalogue features recomputed from visible faults; check individual features for leakage and compare to the internal holdout best. Record evaluator version, withheld positives and confidence interval.
  3. Compare the candidate surface and final dots to each available registry raster. A correlation over 0.90 or dot overlap over 70% within 3 pixels is lane drift; stop. Missing comparisons mean uniqueness is unverified.
  4. Check a single-band GeoTIFF against the official sample's CRS, dimensions and transform, and validate the actual pixels. The local preflight additionally requires all pixels to be finite, unmasked, and in [0,1], a conservative policy pending verified footprint rules. Passing it alone is not approval.
  5. Only after all gates pass and a separate selector approves a slot, open the competition, choose the validated file on the submission form, add the note and submit. Save the organizer receipt. An internal estimate is not an organizer score.

If the form says “Predicted values must be in range [0, 1],” stop and inspect actual pixels including nodata and masked areas. Do not merely rename or clip a file without rerunning all applicable gates.

Local format preflight

From the repository, install dependencies then run python scripts/validate_raster.py path/to/candidate.tif path/to/official_sample.tif. It prints JSON, SHA-256 and individual checks. A passing preflight is not proof of a strong score, uniqueness, official acceptance or permission to submit.
