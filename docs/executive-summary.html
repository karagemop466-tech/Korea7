2. Why GEMSDOE32 scored 0.2778

GEMSDOE32's file is a strict subset of GEMSDOE25: 44,090 dots become 37,654 after removing 6,436 dots that are 1–2 px from the mapped catalogue. The official metric is DTI = TP / (TP + 0.2·FP + 0.8·FN) with a 300 m triangular kernel. Removing a dot that earns no credit reduces FP and raises DTI; adding a dot helps only if its expected credit exceeds 0.2·DTI. At DTI≈0.28 the threshold is ≈0.056. The removed dots are catalogue-adjacent, and the test set is new faults not in the catalogue, so those dots are likely false positives. That is the mechanism behind the +0.0178 gain.

But it is not a new discovery: the file is 100% within 3 px of GEMSDOE25, and the nine focus-site files are 97.6–100% contained in one another. It is a near-clone, not a unique submission.

3. Can we beat 0.2778?

Yes, with a different allocation of the same published recall. The new file treats each published score as a linear measurement of the hidden truth field and inverts the system on a 400 m presence design. It emits one dot per block in descending expected-credit order, with a hard 70% 3 px overlap cap against the nine focus sites. The result is a 106,922-dot raster with an estimated DTI of 0.386 (LOO sd 0.066). The blockinv3 reference uses a 300 m design and 128 published pairs; its estimate is 0.3138 with a much tighter LOO error (0.0206, ρ=0.958).

Honest caveat: the 0.386 estimate is in-sample for a 10-raster field and has a wide error bar. It is not an organizer score. The blockinv3 reference is the more reliable estimate. Both are unique against the nine focus sites (worst 3 px overlap 39.8% and 34.7%, respectively, below the 70% cap).

5. How to submit

  1. Download the TIF (or ZIP) from the button above.
  2. Open the official competition, sign in, and go to Submit → Make new submission.
  3. In File to submit, choose the downloaded .tif (or the ZIP containing exactly one TIFF).
  4. Paste the submission name korea7-blockinv-b4-n12000-k106922-20261104T200956Z and the note block-inversion 400m: 106922 dots; est 0.386 (LOO sd 0.066).
  5. Submit. Record the organizer receipt separately from the local estimate.

One scored submission per UTC day. Do not spend a slot on an unvalidated file. If the new file scores below 0.3138, submit the blockinv3 reference the next day.
