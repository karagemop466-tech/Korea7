Step by step

  1. Download the file above. Optionally verify the hash: sha256sum gemsdoe32-korea7-scarprad-b2cov-r100-20261104T201931Z-7dcabf26-zeros.tif must print the SHA-256 above.
  2. Open the competition: drivendata.org/competitions/306/competition-doe-gems and sign in. Check your remaining weekly submission slots on the submission page — spending a slot is your decision; nothing on this site submits for you.
  3. Re-read the current rules and the format section of the problem description (single-band float32 GeoTIFF, EPSG:32611, 100 m, values in [0,1] — this file satisfies all of these on every pixel).
  4. Click Submit / “New submission”. Under File to submit, choose the downloaded -zeros.tif.
  5. In Note (optional), paste exactly: Korea7 E3 scarpXrad concordance b2 greedy kernel-cover 37654 roadctl zeros SGMCcal 0.0963 unique-vs-focus9
  6. Submit once. If the portal errors, screenshot the full message + filename and stop — do not retry with any renamed or regenerated copy; bring the error back to this project (IR-K7-03 is still open).
  7. Record the receipt: submission id, timestamp, and the public score when it appears. Add them to run-card.json (organizer_confirmed_score) — until then every number for this candidate stays labelled HOLDOUT-DTI / PROJECTION.
  8. Remember the prize structure: you must eventually select one submission for both prize rounds before the deadline, without knowing private-set performance. Keep this candidate's receipt with the others you are choosing among.

Why this file cannot produce “Predicted values must be in range [0, 1]”

That error is a whole-raster range check. This file was written by the shared submission_writer.py in its zeros mode and re-read byte-by-byte by two further validators in this repo: single band, float32, EPSG:32611, 3730×3292 with the sample transform, all 12,279,160 pixels finite with min 0.0 and max 1.0, nodata=None (evidence: evidence/writer_bundle.json, evidence/validate_submission_final.json). There is no NaN, infinity, sentinel, or >1 value anywhere in the file for the portal to object to. (Local validation still cannot guarantee portal acceptance — step 6 covers that case.)
