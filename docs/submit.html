How to make a submission, start to finish

Read this first. Steps 1-2 cannot be done from this repository: the competition rasters require a DrivenData login. Everything after that is one command.

Step 1 - get the three files you actually need

Sign in at the competition data page and download into data/:

FileWhy it mattersIf it is missing
numeric_features.tif (or training_features.tif) the multi-band evidence stack; every independent feature is derived from it no model, no submission
labels.tifthe mapped faults: the training target and the source of the catalogue features no holdout, no emission, no submission
sample_submission.tifdefines the required CRS, shape and geotransform; the validator compares against it the validator falls back to the recorded grid and says so

Recorded grid, verified in gems/grid.py: EPSG:32611, 100 m pixels, 3292 columns x 3730 rows, transform (100, 0, 250000, 0, -100, 4520000), i.e. 119.83-116.10 W, 37.44-40.83 N. Confirm it against your own sample_submission.tif before trusting it.

Step 2 - install and build

python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/build_submission.py --data data --out out/submission.tif

Useful flags: --emit topk|threshold|coverage|nms (default threshold, the measured winner), --top-k, --folds, --buffer-px, --registry path/to/registry.json, --no-write to rehearse.

Step 3 - read the run card, not the console

The run card (out/submission.run.json) is the only thing that authorises a slot:

FieldMust show
statusREADY_FOR_SELECTOR. Anything else - including NOT_READY - means do not submit.
gates.format_validtrue (single band, CRS/shape/transform match, finite, inside [0,1])
gates.no_leakage_canary_triptrue (no catalogue feature with AUC > 0.90 on withheld segments)
gates.uniqueness_passtrue, which requires a complete nine-site registry manifest
holdout.mean + ci95HOLDOUT-DTI, segment-blocked, with the CI. Not a leaderboard score.
file.sha256the hash of the exact bytes you will upload

Step 4 - screen for uniqueness

# manifest: JSON array of {site, surface, dots, surface_sha256, dots_sha256}
.venv/bin/python -m gems.registry --candidate out/submission.tif --manifest registry.json

Blocked if the rank correlation with any registry surface exceeds 0.90, or if more than 70% of your positive cells lie within 3 px of one registry raster's positives. Without a manifest the verdict is UNKNOWN, which is a block, not a pass.

Step 5 - upload

  1. Open the competition page and check the current rules, the weekly cap and the submission page's own wording.
  2. Choose out/submission.tif (or a .zip holding exactly that one file) as "File to submit".
  3. Note field (max 140 characters), for example:
    CSE-1: Hessian lineaments + balanced logistic + isotonic calibration + Dinkelbach sparse emission; holdout DTI 0.xx (CI 0.xx-0.xx)
  4. If the form answers "Predicted values must be in range [0, 1]", the file has a NaN or an out-of-range value: run python -m gems.validate out/submission.tif. The writer in this repo cannot produce such a file; the validator will name the failing check.
  5. Record the organizer's receipt separately. Until a receipt exists, the score is unknown, and the holdout number stays labelled HOLDOUT-DTI.

What not to do

  • Do not upload the format probe in docs/downloads/. Its score is exactly 0.0000.
  • Do not upload anything whose run card says NOT_READY because of a uniqueness gap: an unverifiable duplicate is a rules risk and a zero-information submission.
  • Do not report a holdout DTI as a leaderboard score, and do not promote a candidate on a projection.
