Why the nine sites are not the answer

The official metric is a distance-weighted Tversky index with α=0.2, β=0.8 and a 300 m triangular kernel. The test set is new faults not in the USGS catalogue. The nine focus-site files are all off-catalogue dot sets, but they are 97.6–100% contained in one another: they are the same “lattice” with small variations. GEMSDOE32's 0.2778 is a strict subset of GEMSDOE25 after removing 6,436 catalogue-adjacent dots. Removing those dots helped, but the file is still a near-clone. Submitting any of them adds no new information and risks a duplicate flag.

Why the new file is different

The new file is a block-level inversion of published (raster, score) pairs. Each 400 m block gets one dot, placed in descending order of expected kernel credit, with a hard 3 px overlap cap of 70% against the nine focus sites. It is a re-allocation of demonstrated recall, not a copy: exact dot overlap with the blockinv3 reference is only 7.4% (Jaccard 0.035), and its worst 3 px overlap with any focus site is 39.8%. It is the highest-estimate unique file in this repo.

What the estimate means

The estimate is not an organizer score. It comes from a ridge inversion of 10 published (raster, score) pairs with a bounded hidden-truth mass N ≤ 12,512 px. The leave-one-out error is 0.0658, so the honest band is wide. The blockinv3 reference uses 128 pairs and has a much tighter LOO error (0.0206, ρ=0.958); its estimate is 0.3138. Use the new file for the highest estimate, or the reference for the most reliable estimate.

How to submit

  1. Click Download TIF above (or the ZIP).
  2. Open the official competition, sign in, and go to Submit → Make new submission.
  3. In File to submit, choose the downloaded .tif (or the ZIP containing exactly one TIFF).
  4. Paste the submission name korea7-blockinv-b4-n12000-k106922-20261104T200956Z and the note block-inversion 400m: 106922 dots; est 0.386 (LOO sd 0.066).
  5. Submit. Record the organizer receipt separately from the local estimate. Do not call the estimate an organizer score.
One scored submission per UTC day. Do not spend a slot on an unvalidated file. If the new file scores below the blockinv3 reference, use the reference the next day.
